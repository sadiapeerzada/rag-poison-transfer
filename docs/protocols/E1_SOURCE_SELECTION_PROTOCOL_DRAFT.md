# E1 source-selection effectiveness — DRAFT for reuse-inventory review

Prepared 12 November 2026. This supersedes the expansion plan for this milestone only. No protocol freeze or inference authorization is implied. Prior examined HotpotQA data are historically exposed; neither this pilot nor a subset of that cohort may be described as untouched.

Use a 25-question development pilot to validate matching and feasibility. Propose a separate 100–150-question matched study, conditional on cohort availability, exposure review and supervisor approval. Choose IDs without consulting final outcomes; archive the ordered cohort, dataset revision, corpus digest and exposure ledger privately before selection. Development questions are excluded from the proposed study. If only exposed IDs are available, label the study retrospective. Do not substitute unmatched aggregate denominators.

For each query × lexical/semantic-fluent family × intensity {1,3} × seed {42,43,44}, freeze three ordered candidate slots before any screening. Preserve failed slots, generation attempt records, target assignments, exact document bytes and IDs. Use the historical bounded construction rule (semantic maximum two attempts per document, 150 generation tokens; lexical deterministic construction), subject to confirming its native artifact binding. No method receives extra proposals, retries, repair or target resampling. Candidate libraries and candidate-band corpora must be identical across methods and the two source retrievers, BM25 and Dense. Each selected union corpus must be frozen and hashed separately: changing other questions' selections can change retrieval even when one candidate is unchanged.

M1 selects the first valid candidate in frozen slot order. M2 selects uniformly among valid slots with a local Python Random instance; derive its integer seed from SHA-256 of canonical JSON ["E1-M2-v1", experiment seed, query ID, family, intensity]. Record that integer and the Python version. Use the same draw across sources to reduce nuisance variation. M3 screens every valid candidate using only that source's candidate-band corpus and Qwen target exact match; select the first source-successful candidate in slot order, falling back to first-valid. No valid candidate means construction failure for all methods. The helper in `audit_e1_e2_reuse.py` takes the derived integer, fixed library and source-only boolean feedback; it does not generate candidates or perform screening.

All methods share candidate-generation opportunities and budgets. Screening is the M3 intervention and its incremental cost must be reported separately, not hidden in candidate-generation cost. For a strict equal-total-compute sensitivity analysis, perform the same bounded source screens once for all arms but hide feedback from M1/M2. Do not spend unused M1/M2 compute on additional candidates. Share verified identical physical calls; never report them as independent replications.

Freeze source feedback and all M1/M2/M3 selections before exposing final target outcomes. Keep target logs inaccessible to selection code/operators until the seal is recorded. Source screen success is distinct from final source success: re-evaluate the source on each method's final selected union corpus. Dense's final source observation can serve its target role only with exact input/backend parity. Targets are Dense, cross-encoder Reranker and frozen RCD, with identical generator-visible top-k=3 and the same Qwen backend, snapshot, tokenizer, full backend prompt and decoding settings. A final Dense target result must never replace candidate-band screening feedback.

For each method/source/stratum report:

- Construction coverage: valid selections / all assigned questions. Preserve failure types and zero end-to-end contribution; do not impute a generated answer.
- Source success: final source target matches / valid selections; also report / all assignments. Screening success is a separate diagnostic.
- Conditional transfer: final target AND final source target matches / final source target matches. A zero denominator is undefined, not zero. For Dense→Dense identify the self-pipeline control explicitly.
- End-to-end target matching: final target matches / all assignments; valid-only target matching separately. Target matching uses the pinned answer extractor and normalized exact match, independent of poison retrieval exposure.
- Clean-to-poisoned transitions: gold-correct→target, gold-correct→other incorrect, incorrect→target, incorrect→gold-correct and unchanged; additionally report clean target-match→poison target-match so pre-existing errors cannot masquerade as induced attacks. Use a matched clean control for every pipeline/query/backend.
- Cost: physical completed, failed, retried and indeterminate generator calls; construction, screening and final QA separately; retrieval wrapper calls, inner operations, diagnostics, wall time and cache hits separately.

Use paired method differences with question-cluster bootstrap (2,000 replicates, seed 20261026, percentile 95% intervals). Resample question IDs and retain all methods, source/target pipelines, families, intensities and seeds within a cluster. Recompute ratio denominators per replicate and disclose undefined replicates. Seeds are repeated measures, not independent questions. Report pilot descriptively; predeclare primary contrasts M3−M1 and M3−M2 and handle multiple stratum analyses as exploratory unless multiplicity rules are approved.

Reuse requires the exact audit contract in the inventory, including poison identity and full corpus, ordered evidence, effective backend prompt and model/backend conditions. Historical candidate-band feedback may qualify after provenance review; aggregate success cannot reconstruct it. Review inventory, cohort, screening isolation and final cost ledger before freezing this draft.
